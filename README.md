# Визуализация графа зависимостей Cargo

Инструмент варианта 11 практического занятия по конфигурационному
управлению. Программа строит граф зависимостей пакета Rust (Cargo)
без готовых менеджеров пакетов и библиотек разбора зависимостей.

Этап 1 читает настройки из YAML, проверяет каждый параметр
и печатает их в виде `ключ: значение`. Этап 2 по URL репозитория GitHub сам читает Cargo.toml и
печатает прямые зависимости пакета. Этап 3 строит
транзитивный граф поиском в ширину с рекурсией, отбрасывает
пакеты по подстроке и показывает циклы. В тестовом режиме
граф читается из файла, где пакеты названы большими
латинскими буквами. Этап 4 печатает порядок загрузки:
зависимость раньше пакета, который её использует. Менеджер
cargo для получения графа не вызывается. Рисунок появится
на следующем этапе.

## Настройки

Источник настроек — один YAML-файл. Кодировка UTF-8.
Корень файла — набор параметров, лишние ключи запрещены.

| Параметр | Тип | Правило |
| --- | --- | --- |
| `package_name` | строка | Имя пакета Cargo: латиница, цифры, `-` и `_`, первый символ — буква или цифра, длина от 1 до 64 |
| `repository` | строка | При `test_repository_mode: false` — абсолютный URL со схемой `http` или `https`. При `true` — путь к существующему файлу |
| `test_repository_mode` | логический | Некавыченные `true` или `false`. Строка `"false"` не принимается |
| `graph_image_name` | строка | Имя одного файла с расширением `.png`, без каталога |
| `filter_substring` | строка | Подстрока: пакеты, в имени которых она есть, не входят в граф. Пустая строка означает, что фильтр не задан |

Относительный путь тестового репозитория считается от каталога
конфигурационного файла. В вывод попадает уже абсолютный путь:
так видно, что файл действительно найден.

Проверки идут в таком порядке: неизвестные ключи, имя пакета,
режим тестового репозитория, адрес репозитория, имя рисунка,
подстрока фильтра. Сообщается первая ошибка.

## Функции

- `load_config(path)` читает YAML и возвращает проверенный `AppConfig`
  либо выбрасывает `ConfigError`.
- `AppConfig.as_pairs()` возвращает параметры парами ключ-значение
  в порядке задания.
- `format_parameters(config)` собирает эти пары в текст.
- `load_direct_dependencies(config)` скачивает Cargo.toml
  и возвращает прямые зависимости из секции `[dependencies]`.
  Для workspace ищется член с тем же именем, что `package_name`.
  Зависимости разработки не входят в список.
- `format_dependencies(dependencies)` собирает строки `имя версия`.
- `build_graph(root, neighbors, skip)` строит транзитивный граф
  поиском в ширину. Следующий уровень обходится рекурсией.
  Имена с подстрокой `skip` не учитываются. Цикл не приводит
  к бесконечному обходу и попадает в результат.
- `build_test_graph(config)` читает файл, где пакеты названы
  большими латинскими буквами: `ИМЯ: ЗАВИСИМОСТЬ ЗАВИСИМОСТЬ`.
- `build_cargo_graph(config, direct)` продолжает граф по crates.io,
  начиная с прямых зависимостей из Cargo.toml.
- `format_graph(graph)` печатает рёбра и найденные циклы.
- `load_order(graph)` ставит зависимости перед пакетом, который
  их использует. Сам пакет оказывается последним. При цикле
  каждый пакет попадает в список один раз.
- `format_load_order(order)` печатает этот список.
- `main(argv)` разбирает аргумент `--config`, печатает параметры,
  прямые зависимости и граф. В тестовом режиме прямые зависимости
  Cargo не запрашиваются: граф берётся из файла.
  Код возврата `0` означает успех. Ошибка пишется в stderr,
  код возврата — `1`. Если не передан `--config`, код возврата — `2`.

## Сборка и тесты

Нужен Python 3.11 или новее.

```bash
python -m pip install -r requirements.txt
```

В зависимостях есть `types-PyYAML`: без него `mypy` считает
импорт PyYAML нетипизированным.

Запуск тестов из корня репозитория:

```bash
python -m unittest discover -s tests -v
```

На Windows то же самое выполняет `python`, путь к исходникам
скрипты запуска выставляют сами.

## Примеры

Успешный запуск, удалённый репозиторий:

```bash
run.bat --config config.yaml
```

```text
package_name: serde
repository: https://github.com/serde-rs/serde
test_repository_mode: false
graph_image_name: serde.png
filter_substring:
прямые зависимости:
serde_core =1.0.229
serde_derive 1
```

Список версий берётся из текущего Cargo.toml репозитория serde
и со временем может измениться. После прямых зависимостей
этап 3 печатает транзитивный граф. В тестовом режиме Cargo
не вызывается: граф читается из файла.

Строка файла: `ИМЯ: ЗАВИСИМОСТЬ ЗАВИСИМОСТЬ`. Имена — большие
латинские буквы. Пустой список после двоеточия значит, что
исходящих рёбер нет.

```bash
run.bat --config examples/test_cycle.yaml
run.bat --config examples/test_filter.yaml
```

`test_cycle.yaml` показывает цикл `A -> B -> C -> A`.
Порядок загрузки при этом `C`, `B`, `A`: каждый пакет один раз.
`test_order.yaml` для ромба `A -> B, C`, `B -> D`, `C -> D`
печатает `D`, `B`, `C`, `A`. `test_filter.yaml` выкидывает
пакеты, в имени которых есть `C`, и в порядке их уже нет.

## Сравнение с Cargo

Направление порядка совпадает с компиляцией Cargo: зависимость
раньше пакета, который её использует. Состав списка и взаимный
порядок соседей могут отличаться.

- В список входят только обычные зависимости из `[dependencies]`
  и normal-записи crates.io. `dev-dependencies` и
  `build-dependencies` не участвуют. Cargo при сборке
  дополнительно компилирует build-зависимости и зависимости
  включённых features.
- Точная версия вида `=1.2.3` берётся как написана. Иначе
  программа берёт `max_stable_version` с crates.io, а не версию
  из `Cargo.lock`. Транзитивный набор поэтому может быть другим.
- Если готовы сразу несколько зависимостей, раньше печатается
  та, что раньше указана в манифесте или в тестовом файле.
  Cargo выбирает порядок единиц компиляции по своим правилам.
- Обычный `Cargo.lock` цикл не содержит. Тестовый граф цикл
  показывает и всё равно печатает каждый пакет один раз.
- Файл из больших латинских букв Cargo не читает. Это отдельный
  режим, чтобы проверить порядок без сети и без `cargo`.

Тестовый репозиторий:

```bash
run.bat --config examples/test_repository.yaml
```

Ошибки по параметрам (на Linux и macOS — `sh run.sh`):

```bash
run.bat --config examples/errors/empty_package.yaml
run.bat --config examples/errors/bad_url.yaml
run.bat --config examples/errors/missing_test_file.yaml
run.bat --config examples/errors/bad_mode.yaml
run.bat --config examples/errors/bad_image.yaml
run.bat --config examples/errors/bad_filter.yaml
run.bat --config examples/errors/broken.yaml
run.bat --config examples/errors/unknown_key.yaml
```

Каждая команда печатает в stderr строку, которая начинается
с `ошибка конфигурации:` и называет неверный параметр.
Код возврата при этом равен 1.
